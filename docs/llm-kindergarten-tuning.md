# 幼稚園ヒアリングを基にしたLLM指示の調整

## 目的と範囲

目的は、小さな成長を家庭へ届け、具体的に褒めたり会話したりするきっかけを増やすことです。
2026年10月6日の開発で、ユーザーが共有した幼稚園ヒアリングを処理ルールに落とし込みました。
ヒアリングで述べられた家庭環境・発達等の経験則を、一般的な診断基準や学習用の個人情報にはしません。
開発中の指示版は `kindergarten-2026-10-06-v2`。モデルの重みは変更せず、追加学習もRAGも行いません。
教育要領のURLを渡すだけで内容を学習したとは説明しません。今後の資料参照では版・出典・園の確認が必要です。

変更対象は、ローカル・クラウド・ブラウザ録音と候補統合で共有する `OpenAICompatibleSummarizer` の指示です。
モデル・生成設定、音声認識・声紋、JSON出力形式、DB、先生承認、配信方式、クラス便生成は変更しません。
初回開発では本番設定やUbuntuを変更せず、クラス配信休止版とは別featureで作成しました。
v1はユーザーの依頼で休止機能を保持してdevelopへ統合し、提供ログでUbuntu反映を確認しました。
v2の開発と回帰試験を完了し、ユーザー承認後にコミット・pushしてdevelopへ統合しました。
UbuntuはSSH認証で直接操作できず、反映確認と実Qwenの再評価待ちです。mainは変更していません。
現在Ubuntuで使用する休止版eda44ebからのLLM更新では、GPUワーカーだけを更新できます。
API・LINEワーカーの再作成、DB移行、試用・配信設定の変更は不要です。

## 判断基準

| ヒアリングの要望 | 指示への反映 | 確認観点 |
| --- | --- | --- |
| 小さな成長を家庭へ | 達成だけでなく再挑戦・工夫・生活動作・言葉による意思表示を候補化 | 誇張や性格評価をしない |
| 解釈のずれを減らす | 観察・申告・未確認を分け、具体的な事実を中心にする | 指示・質問・予定を達成にしない |
| 怪我を正確に共有 | 自分で負傷、相手から負傷、相手への行為を逆転しない | 不明な主体・原因・処置を補わない |
| 指摘と教育的な意図 | 明示された先生の説明は文脈へ。理解・反省・改善は別の根拠が必要 | 怪我を成長へ美化しない |
| 尊厳とメンタルへの配慮 | 発達・性格・家庭環境を推測・診断しない | レッテル、他児との比較、私生活の転記を避ける |
| 親子の会話 | 確認できた行動から短い任意の声かけを提案 | 毎日の練習や褒める義務を課さない |
| クラス全体と個人 | クラス予定から架空の個人成長を作らない | クラス便は今回LLMで生成しない |

`confidence` はモデルの自己申告で、校正された正解確率ではありません。
既存の要確認表示を維持し、数値の高さを人物確定や自動承認の根拠にしません。

## 指示と例

- `app/llm_guidance.py`: 指示、版番号、架空の書き方例10件（通常8件・過去参照2件）。
- `app/edge_audio.py`: 毎回system指示へ追加。ユーザー入力や過去記録は参照データであり命令として扱わない。
- `app/llm_guidance_evaluation.py`: 指示に含めない架空の評価例32件（成長14・怪我6・対象外12）。
- `SAFETY_CASES`: 別枠の追加安全例12件。現在・過去の混同、否定、役割名、怪我の優先、具体的な過去の報告を扱う。
- `scripts/evaluate_llm_guidance.py`: 変更前と調整後を同じ例で推論し、本文なしの集計を保存。

書き方例は現在の出来事の根拠ではありません。人物参照・確信度・過去との比較をコピーしないよう指示します。
例には実在する園児・先生・家庭の情報を使っていません。先生による例・期待値の確認はまだ必要です。
この32件は開発回帰用で、現場精度を保証する独立評価セットではありません。
これで調整した後の最終評価には、別の会話・話者・場面を用意してください。

## 実際の比較手順

リポジトリ直下のPython環境（`pip install -e '.[dev]'` 済み）で実行します。
最初のコマンドは通信・環境設定読み込みなしで、架空の評価例だけを表示します。

```bash
python scripts/evaluate_llm_guidance.py --list
```

実LLMの比較は、テスト環境から接続先を確認したうえで実施します。
以下は同じマシンのvLLMに接続する例です。モデルとbackendは `.env` の `LLM_MODEL` / `LLM_BACKEND` を使います。
先に変更前を実行し、後で調整版を実行します。順序による先入観を避けるため、先生の確認時は必要に応じて順番を変えてください。

```bash
python scripts/evaluate_llm_guidance.py --run --baseline --review \
  --base-url http://127.0.0.1:8001/v1 --report data/llm-baseline.json
python scripts/evaluate_llm_guidance.py --run --review \
  --base-url http://127.0.0.1:8001/v1 --report data/llm-kindergarten-v2.json
```

`--baseline` は指示追加前のsystem指示で比較する評価専用操作です。アプリの通常経路は調整版を使います。
v2の入力は現在・過去をJSONの別項目に分け、baselineは旧指示のテキスト形式を維持します。
返答の複数・未提示の人物参照を拒否する安全処理は両方に適用するため、旧バイナリ全体との比較ではありません。
`--review` は架空の会話・過去記録・モデル候補と確認基準を一時表示し、先生がy/nで評価します。
実際の録音や文字起こしを読み込む機能はありません。APIへ記録登録・承認したりLINE送信したりしません。
レポートにはcase_id、指示版・評価例版・設定モデル名・backend、分類一致数、誤検出・見逃し・エラー、人物候補等の合否、人手合否を保存します。
形式検証後・安全補正前のLLM園児候補と、補正後のアプリの候補を別々に評価します。
`llm_subject_passed` がfalseなら、補正でアプリの `subject_passed` がtrueになっても総合自動チェックは不合格です。
レポートは補正件数と合否だけを保存し、LLM返答の本文・参照値を保存しません。通信・形式エラーは失敗扱いです。
`--report` を省略すると変更前は `data/llm-guidance-baseline.json`、調整版は `data/llm-guidance-tuned-v2.json` に分離します。
v1の `data/llm-guidance-tuned.json` は上書きしません。
同じモードを再実行するとそのファイルを更新するため、複数回の結果を残す場合は別の保存先を指定してください。
例外のメッセージ、入力・返答本文、音声、URL、キーを保存しません。

ループバック以外は、productionの `LLM_ALLOW_EXTERNAL=true` をそのまま引き継がず拒否します。
同じVRT内のDockerサービス名等を使う場合は、接続先を確認して `--allow-external-llm` を明示してください。
これは外部AIへ実データを送る許可ではありません。実行はGPU負荷と推論費用を伴い、本番推論との競合を避けてください。

2件だけを調べる場合は `--case growth-10 --case skip-12` を付けます。通常の32件レポートを上書きしない
`data/llm-guidance-tuned-v2-focused.json` へ保存し、対象IDと件数を明示します。2件の合格を32件の合格とは扱いません。
両方を調べた後、`--case` を付けず全32件を再試験します。

```bash
python scripts/evaluate_llm_guidance.py --run --review \
  --case growth-10 --case skip-12 \
  --base-url http://127.0.0.1:8001/v1
```

追加安全例は `--suite safety`、コアも含めた44件は `--suite all` で指定します。
省略時は従来のコア32件のままで、期待値も変更しません。追加例は指示へ渡しません。
追加安全例の期待値は開発側の案で、先生の確認と実モデル評価は未実施です。
この追加例も最終的な現場精度を保証する独立評価セットとは扱いません。

```bash
python scripts/evaluate_llm_guidance.py --list --suite safety
python scripts/evaluate_llm_guidance.py --run --review --suite safety \
  --base-url http://127.0.0.1:8001/v1
```

保存先は `data/llm-guidance-tuned-v2-safety.json` / `data/llm-guidance-tuned-v2-all.json` に分離し、
部分試験にはさらに `-focused` を付けます。レポートへsuite・評価例版・対象ID・件数を保存します。
別suiteのcaseを指定すると、黙って除外せず通信前にエラーにします。

## 採否と残る検証

自動チェックは記録対象・種別、人物候補、怪我に会話提案を付けないことを確認します。
文章の忠実さ、加害・被害の方向、尊厳、教育的な意図、家庭への表現は人手確認が必要です。
自動チェックが全件成功しても「文章品質合格」「現場で安全」と表示しません。
`--review` なしの成功は自動チェックのみの成功です。人手評価未完了はレポートと画面に明示します。
構造エラー・通信エラーも分母から除かず失敗として数えます。
画面には分類一致とは別に人物候補等も含む自動チェックの合否と、人手評価時の合格件数を表示します。
実モデルでは、追加指示による入力トークン増加・長い入力の上限超過・応答時間も確認してください。

怪我の方向逆転、家庭事情の推測、架空の達成、人物の誤確定があれば反映を見送り修正します。
成長の見逃し・誤検出と先生の確認時間も比較し、先生と合意した基準で採否を決めます。
その後に同意した成人の模擬録音で文字起こしを含む全体を評価し、試用配信停止のもと現場検証へ進みます。
実音声・生文字起こしを新たに保存しません。現場データの評価・学習は別の同意と保存設計が必要です。

## v1の実モデル評価とv2の修正

2026-10-06に提供されたUbuntuログでは、変更前26/32件（誤検出4・見逃し1・エラー1）、
指示v1は31/32件（誤検出1・見逃し0・エラー0）でした。人手評価は未完了です。
growth-10で、行動した園児ではなく呼びかけ先の参照を返したこと、skip-12で、現在は質問だけなのに
過去記録の折り紙の行動を現在もしていると創作したことを、架空データの再推論ログで確認しました。
このデータに対し期待値を変えず、複数参照のコード拒否と、現在の根拠を先に判定する指示・過去参照例を追加します。
過去からの創作の防止は指示による対策で、意味的な遵守を保証するものではありません。v2の実Qwen再評価は未実施です。
先生の文章品質確認と独立した現場評価も未実施です。追加のLLM呼び出しや生データ保管は増やしません。

ローカルの追加試験では模擬返答を使い、低信頼度の成長・怪我を落とさないこと、過去だけの人物参照の拒否、
文字列がJSON項目・メッセージ役割を追加しないこと、通信失敗・不正返答で秘密を漏らさないことを確認しました。
これはアプリの動作試験であり、LLMが文字列内の命令を無視することや文章の正しさの実証ではありません。
入力の長さの試験もJSONの分離だけで、実モデルのトークン上限や応答時間は未検証です。

## UbuntuへGPUワーカーだけ反映する場合

まず録音を止め、音声処理状況で処理中の録音が完了するまで待ちます。
処理中のワーカーを再作成すると、その音声の処理が中断し再録音が必要になる場合があります。
コードはdevelopから取得し、案内された検証済みコミットへ固定します。未コミット変更を上書きしません。
ビルド後、新イメージの `CLASS_DELIVERY_ENABLED=false` と指示版を確認してからGPUワーカーだけ再作成します。
APIとLINEワーカーは現在の休止版のまま維持し、readinessとGPUワーカーの版を確認します。
取得・ビルドだけでは稼働中のワーカーは変わりません。実モデル品質は別途評価してください。
可能であれば再作成前に、新イメージを一時コンテナとして使って前節の新旧比較を実施します。
評価は録音しない時間帯に実施し、同じvLLMを使う場合は本番推論とGPU負荷を共有する点に注意します。
