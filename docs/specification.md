# Small Step 共通仕様

この文書は機能・権限・データの扱いを横断する仕様の入口です。2026-10-02時点のリポジトリの
実装・設定例を照合して整理しています。配備先の設定・動作・モデル精度は別途確認します。
領域ごとの詳細は[技術構成](architecture.md)、操作は[使い方](usage.md)、導入は[手順書一覧](README.md)を参照します。

## 目的と利用者

園内での出来事を「成長の記録（growth）」「けがの記録（injury）」の候補にし、先生が園児と文面を
確認した後だけ保護者へ配信します。記録を作る入口は、匿名化済みテキスト、手入力、端末のクラウド音声、
スマートフォン録音です。AIによる候補生成と先生による承認は別の処理です。

| 利用者 | 認証 | 操作範囲 |
| --- | --- | --- |
| 先生 | Supabase access token | 自分が担当する記録のレビュー・履歴・通知、自分の録音、本人の声紋操作 |
| 先生管理者 | 同上、DBのschool_admin権限 | 同じ園の記録と通知、園児・先生・端末・設定・監査・CSV・Notion同期 |
| 録音端末 | 端末専用APIキー | キーに紐付く園・担当の記録／音声投入と死活通知 |
| 保護者 | 期限付きアーカイブトークン | 対象園児の送信済み通知のみ |
| LINE | 生ボディに対する署名 | 招待コードによる保護者連携 |

`AUTH_MODE=development` はローカル専用の管理者相当です。本人認証を要求する録音や声紋などの経路は、
このモードで代用できません。権限判定はFastAPIで行い、ナビゲーションの非表示だけには依存しません。
園スコープ、記録担当、録音所有者の制約は[認証・認可](architecture/auth.md)を正とします。

## 記録の作成・レビュー・配信

1. 各入口から `pending_review` の候補を作ります。音声に具体的な園児の出来事がなければ、処理は正常終了し記録を作りません。
2. 一般の先生は自分の担当記録、先生管理者は同じ園の記録を確認します。管理者だけが未承認記録の担当を変更できます。
3. 承認には同じ園の在籍園児が必須です。録音PWA由来は明示選択と `child_confirmed=true` も必須です。
4. 承認で記録を `approved` にし、通知を1件作成します。却下は `rejected` で終わり、通知を作りません。
5. 本番通知は予定時刻以後にLINEワーカーが送り、成功時に通知を `sent`、記録を `dispatched` にします。
   承認API自身はLINEを送信しません。試用承認は `approved` のままで配信しません。

| 承認条件 | 通知の初期状態 | 動作 |
| --- | --- | --- |
| 園または記録が試用 | trial | 送信先を保持せず配信なし |
| 本番・LINE連携済み | pending | 予定時刻以後に送信 |
| 本番・LINE未連携 | waiting_guardian_link | 連携後に送信待ちへ移行 |
| 園児未選択／退園済み | 通知を作らない | 承認を拒否 |

配信日時の明示指定を優先します。未指定なら、けがは即時、成長は園のタイムゾーンと `digest_time`
（新規園の既定17:00 / Asia/Tokyo）に基づく次回時刻です。園の時刻変更は、その後の承認に適用します。
既存通知は自動変更せず、管理者の再予定操作を使います。失敗した送信は通常実行で自動再送しません。
詳細な状態と一意制約は[データモデル](architecture/data-model.md)、送信・連携再開は[外部連携](architecture/integrations.md)を参照します。

## 園別試用モード

APIの新規園は `trial_mode=true` です。既存園の設定は移行で保持します。試用由来の記録・ジョブ・録音は
`is_trial` を保持し、本番へ切り替えても配信対象へ戻しません。承認時と送信直前にも園の設定を確認します。
本番から試用へ切り替えると未承認記録・未完了音声・未送信通知等を永久に試用扱いへ移します。

試用通知は終端状態 `trial` です。LINE配信、保護者アーカイブ掲載、Notion同期、再送、再予定、送信済み変更を
許可しません。運用責任者への障害通知は別経路です。本番への切り替えは管理者の配信確認を必要とします。
送信開始済みのLINEを取り消す機能ではありません。[試用導入手順](school-trial-runbook.md)に切替と移行の条件をまとめています。

## 音声・文字起こし・候補の保存境界

| 経路 | APIへ送るもの | 処理場所・保管 |
| --- | --- | --- |
| localエッジ処理（既定） | 加工済みテキスト | 園内で文字起こし・匿名化。音声は既定で処理後に削除 |
| cloudエッジ処理（明示有効化） | 生音声と安全なジョブ情報 | APIが短命ファイルへ保存しGPUワーカーが処理。DBはメタデータのみ |
| 録音PWA（明示有効化） | 分割生音声 | 端末IndexedDBとサーバー短命ファイル。既存GPUワーカーで処理 |
| 声紋登録・本人確認（任意） | 本人の登録／照合音声 | 短命ファイルから暗号化代表特徴量を生成。元音声を削除 |
| プロコン処理表示（任意） | 試用録音と録音前の同意 | 文字起こしとLLM入出力の暗号化短命ファイル。終了後5分以内、録音者本人だけ取得 |

**音声バイトと生の文字起こしは業務DBへ保存しません。** クラウド／PWAでは生音声がAPIに届くため、
「全経路で音声が園外へ出ない」とは説明しません。通常APIやログは生の文字起こしを返しません。
プロコンの例外表示は試用園・専用キー・本人ログイン・録音ごとの同意を必要とし、架空の会話だけで実演します。
匿名話者分離は本人を特定せず、任意の声紋照合とは別です。

音声は成功・失敗・破棄・期限切れで削除し、ワーカーが後片付けを再試行します。ワーカー停止中は削除も停止します。
期限切れはアクセス・処理可否の期限であり、その瞬間の物理削除を保証するものではありません。
匿名化は完全性を保証せず、未登録名・誤変換を含め先生が本文を確認します。
LLMは既定でループバックだけを許可し、Dockerサービス名を使う構成も `LLM_ALLOW_EXTERNAL=true` の明示が必要です。
有効化と保管期間は[音声仕様](architecture/audio-pipeline.md)と[処理表示手順](recorder-processing-demo.md)を参照します。

## 録音PWAの契約

既定の連続モードは60秒ごとに別セッションとして確定・自動送信します。停止時の端数も送信し、
1回の開始は最長12時間です。手動モードは累計60分以内、停止後に送信または破棄を選びます。
1セッションから最大1件の承認待ち記録を作り、セッション間の文脈統合は行いません。
端末の未送信保存は最大3件・24時間で、3件に達したら録音を一時停止します。再開は利用者の操作です。

画面ロック・スリープ・強制終了中の常時録音は保証しません。音声受付後の進捗確認はGETだけを使います。
区間の部分失敗は記録へ警告を付け、既知のけがの統合に失敗した場合は全体を失敗にします。
途中結果をDBへ保存しないため、クラッシュした録音処理の途中再開は行いません。
園児候補は承認まで `child_id` へ昇格させず、先生候補も管理者の担当変更操作まで責任者を変えません。
詳細な再送・認証更新・候補条件は[音声](architecture/audio-pipeline.md)と[画面](architecture/frontend.md)にあります。

## 資格情報・監査・バックアップ

端末キー、LINE招待コード、保護者アーカイブトークンはハッシュだけをDBへ保存し、発行時だけ平文を表示します。
再発行で以前のものを失効させます。保護者URLの秘密部分はフラグメントからsessionStorageへ移してURLから消します。
先生のaccess tokenもsessionStorageへ保存し、パスワードはSupabaseだけが扱います。
先生招待を有効にしたAPIだけがサーバー専用secret keyを使用し、ブラウザへ返しません。

監査のDB行は園ID・実行先生ID・操作種別・対象種別・日時等を持ちます。対象の内部ID、園児名、本文、音声、
文字起こし、LINE ID、鍵は保存しません。画面／CSVは操作・日時・実行者表示名を示します。
保存スキーマと表示項目を区別します。通常業務バックアップはpublicスキーマを対象とし、音声ファイル、
声紋特徴量／声紋ジョブのデータ行、Supabase Auth、Storageを対象外とします。
[データモデル](architecture/data-model.md)、[認証](architecture/auth.md)、[バックアップ手順](operations/backup-monitoring.md)を参照します。

## 配信構成・運用開始の条件

SvelteKitを `app/frontend_dist/`、録音PWAを `app/recorder_dist/` へビルドし、FastAPIが配信します。
`/teacher/*` は200.htmlのSPA fallback、`/guardian/` は静的ページ、`/rec/` は機能有効時だけ静的配信します。
業務APIは同一オリジンですが、ログイン・パスワード設定・録音PWAのtoken更新はSupabaseへ直接通信します。

SQLiteはローカルで起動時に自動移行し、本番PostgreSQLはAPI起動前に明示的に移行を適用します。
本番はSupabase認証、非SQLiteのDB、完全なUIビルドを必要とします。公開入口はHTTPSにし、APIの8000番を直接公開しません。
機能有効時の追加設定も検証します。Docker healthはAPI・DBの起動確認、readinessは移行・設定・ワーカー生存を含む
運用判断です。モデル精度・録音成功・外部配信まで保証するチェックではありません。
[デプロイ仕様](architecture/deployment.md)と[配備先の確認一覧](operations/acceptance.md)を使います。
