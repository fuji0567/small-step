# Small Step 録音

`/rec/` で配信する、先生向けの独立録音PWAです。既存の `frontend/` とは依存関係とビルド成果物を分離しています。

## 開発

Node.js 24.19.0を使用します。

```powershell
npm ci
npm run format:check
npm run lint
npm run check
npm run test:unit
npm run build
```

`npm run build` は `app/recorder_dist/` を生成します。開発サーバーは `/api/v1` を `127.0.0.1:8000` へ転送します。

録音中は画面を前面に保つ必要があります。音声は約1分ごとに独立ファイルとしてIndexedDBへ保存し、受付完了・破棄・24時間経過で端末から削除します。自動再送は、手動モードで送信を選んだ録音と、連続モードで開始時に自動送信へ同意した確定済み区間を対象とします。アクセストークンと更新トークンは `sessionStorage` だけに保存し、Service WorkerはAPI応答・認証情報・音声をキャッシュしません。

既定の連続モードは、明示的な開始後に60秒ごとに別セッションとして自動送信し、録音を続けます。
停止・一時停止時の端数も送信します。開始から最長12時間、未送信が3件に達したら一時停止し、再開には利用者の操作が必要です。
手動モードは最長60分で、停止後に「送信する」または破棄を選びます。
既存GPUワーカーが1セッションから承認待ち記録を最大1件作り、先生用「音声処理状況」に進捗と部分失敗を示します。
セッション間の文脈統合は行いません。音声は区間確定後に処理するため、真のストリーミング認識ではありません。
任意の声紋照合は担当候補の提案だけで、実際の担当変更には先生管理者の確認操作が必要です。
有効化と実機試験は [VRT録音デモ導入手順](../docs/recorder-vrt-runbook.md)を参照してください。

## 送信後の進捗

受付画面はワーカー待ち・処理中を約5秒ごとに確認し、完了した区間数を表示します。
記録が作られた場合は先生用レビュー画面へ進めます。候補なしの正常完了、部分失敗、処理失敗、期限切れも区別します。
承認前にLINEへ送ることはありません。

状態確認は認証付きGETだけを使い、同時取得を避けて15秒でタイムアウトします。通信失敗時は10・20・40・最大60秒へ
確認間隔を延ばし、復旧後は5秒へ戻します。「状態を再確認する」で待機を解除できます。
画面非表示・オフライン中は取得を中断し、復帰時にすぐ確認します。401では既存の更新トークンで1回だけ認証を更新し、
なお認証できなければログインへ戻ります。403・404では確認を止め、機能設定や録音者の確認を案内します。

追跡対象と表示用進捗はメモリだけに保持します。画面を離れた後や再読み込み後は先生用の音声処理状況で確認してください。
待機画面への移動はサーバー処理を取り消しません。完了後は自動確認を止め、音声を再送しません。
