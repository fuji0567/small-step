# 先生管理画面からの招待メール

先生管理者が自分の園の先生を登録し、その画面から本人へ招待メールを送る機能です。
最初の管理者の招待は従来どおりSupabase Dashboardから行います。

## サーバー設定

Supabaseの同じプロジェクトで、サーバー専用のsecret keyを取得します。
その値はチャットやGitへ貼らず、Ubuntuの保護された `.env` だけに設定します。
ブラウザの公開キーと置き換えないでください。`VITE_` や `PUBLIC_` の環境変数にしないでください。

```dotenv
AUTH_MODE=supabase
TEACHER_INVITATIONS_ENABLED=true
SUPABASE_SECRET_KEY=サーバー専用の秘密キー
TEACHER_INVITATION_REDIRECT_URL=https://app.otayori-ai.com/teacher/
```

接続先と招待後URLはHTTPS必須です。招待後URLは `/teacher/` で、クエリやフラグメントを付けません。
SupabaseのAuthenticationのURL Configurationで同じURLをRedirect URLsに許可します。
標準の招待テンプレート（ConfirmationURL）を使います。PKCEや独自のtoken_hashテンプレートは本画面の対象外です。

Supabaseの標準メール送信は制限があり、プロジェクトのチームに登録していない宛先に送れない場合があります。
園の先生など外部の宛先へ送る前に、Supabaseで独自SMTPと送信元を設定してください。
受信箱・迷惑メール・SMTP設定・送信上限も確認してください。
公式: [招待API](https://supabase.com/docs/reference/python/auth-admin-inviteuserbyemail)、
[メール送信設定](https://supabase.com/docs/guides/auth/auth-smtp)、
[APIキー](https://supabase.com/docs/guides/api/api-keys)。

コードを取得し、DBをバックアップしてから、API・移行イメージをビルドします。
今回の移行 `0028_teacher_invitations` を適用し、APIを再作成してください。
古いコードの常駐ワーカー・監視も新しいイメージへ更新します。

## 操作

1. 管理者として先生管理画面を開き、名前とメールを入力して「登録して招待を送る」を押します。
2. 先生登録後に、その登録済みメールへ招待を送ります。通常の先生権限で登録されます。
3. 受信した先生がメールのリンクを開き、自分のパスワードを2回入力します。
4. パスワード設定後に先生情報へ紐付けて画面を開きます。次回からはメールとパスワードでログインします。

既存の「招待待ち」の先生は「招待メールを送る」、送信済み・未ログインの先生は「招待メールを再送」を使います。
停止中・メール未登録・認証連携済みの先生は送信できません。同じ先生への送信は1分以上空けます。
タイムアウトでは実際には送信済みの場合があるため、メール到着を確認してから再試行してください。
失敗しても先生登録は残ります。「登録」をもう一度押して同じ先生を増やす必要はありません。
既にSupabaseのログインアカウントがある場合は既存パスワードでログインします。パスワード再設定はSupabase側で行います。

送信済みは配信受付の表示であり、受信・本人ログイン完了を保証しません。
招待後URLの設定待ちトークンはメモリだけにあり、離脱・再読み込みでは失われます。
期限切れの場合は管理者へ新しい招待を依頼してください。
招待送信を無効にしても既存の先生情報・ログインアカウントは削除しません。

## 安全性

送信先・園・権限はサーバーがDBから確認します。クライアントが任意の宛先やredirectを指定するAPIではありません。
秘密キーを公開認証設定や一覧へ返しません。プロバイダーの応答本文や招待トークンはDB・ログへ入れません。
DBへ保存するのは送信試行時刻・送信受付時刻だけです。本人のパスワードはSupabaseだけが扱います。
