# プロコン用：録音から記録候補までの処理表示

実際の文字起こしとLLMの入出力を確認し、実演しながら処理を説明するための試用専用機能です。
AIの内部思考を取得・生成するものではありません。LLMの入力・応答を再実行せず、その処理で実際に
使った内容と、アプリが行った形式検証・照合・記録作成結果を表示します。

## 先に準備すること

- 架空の園・園児・先生だけを使います。園児候補も実演する場合は架空の名前と「録音で呼ぶ名前」を登録します。
- 管理者が「園の設定」で試用モードを有効にします。試用記録は保護者への配信・Notion同期・保護者アーカイブから除外されます。
- `AUTH_MODE=supabase` の本人ログインが必要です。認証を省略するdevelopmentモードではこの表示を使えません。
- APIとGPUワーカーに `RECORDER_DEMO_TRACE_ENABLED=true` と同じ専用暗号化キーを設定します。

キーはUbuntuで次のように生成できます。出力は秘密情報なので、チャットやGitへ貼らず、保護された`.env`だけに設定します。
声紋暗号化キーと同じキーは使わないでください。

```bash
sudo docker compose -f compose.yaml -f compose.vrt.yaml exec -T api \
  python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

```dotenv
RECORDER_DEMO_TRACE_ENABLED=true
RECORDER_DEMO_TRACE_ENCRYPTION_KEY=生成した専用キー
```

コード取得後はAPIとGPUワーカーをビルドして再作成します。本機能はDBスキーマを追加しません。
未適用の以前の移行がある場合は、通常の導入手順どおり先に適用してください。

```bash
sudo docker compose -f compose.yaml -f compose.vrt.yaml build api gpu-worker
sudo docker compose -f compose.yaml -f compose.vrt.yaml \
  up -d --no-deps --force-recreate --wait gpu-worker api
```

## 実演の操作

1. 先生として `/rec/` を開きます。
2. 待機画面の「プロコン用の処理表示」で、次の録音内容を一時表示する同意チェックを入れます。
3. 録音を開始し、架空の園児の具体的な出来事を話します。連続録音は60秒区間ごと、手動モードは停止・送信後に処理されます。
4. 受付後、画面下の「直近の録音の処理内容を表示」を押します。処理待ちなら約5秒ごとに確認し、完了後に内容を表示します。
5. 文字起こし、LLMへの指示、匿名化後の入力、実際のJSON応答、形式検証・アプリが採用した候補、最終判定を順に開いて説明します。
6. 作成された記録候補へのリンクから、園児・担当・本文を確認して確定する先生の役割を説明します。

同意は録音開始時に固定し、各送信区間に引き継ぎます。既存の録音の内容を後から復元する機能ではありません。
連続録音は直近の受付区間に表示が切り替わるため、説明中は録音を停止するか一時停止すると確認しやすくなります。
匿名話者ラベルは録音内の区別であり、そのまま先生の本人特定を意味しません。
照合結果は候補の有無と先生確認の要否です。声紋・照合スコア・秘密キーは表示しません。
発話がなければLLMの呼び出しを省略します。`recordable=false`なら記録を作らず、
不正なJSONや形式なら候補として採用しません。モデルが返していない個別の理由を推測して説明しません。
再試行・複数区間の候補統合は別の段階として表示します。

## 保存・消去・アクセス範囲

- 通常のDB、監査ログ、ワーカーログ、ブラウザの保存領域には文字起こしやLLM入出力を保存しません。
- 明示同意した試用録音だけ、処理中のメモリで収集し、終了時に専用Fernetキーで暗号化して一時ファイルに保存します。
- 置き場は `RECORDER_SESSION_DIR` の親にある `recorder-demo-traces/` です。VRTでは共有`api_data`の `/app/data/recorder-demo-traces/` です。
- フォルダは0700、ファイルは0600で、静的URLでは配信しません。DBバックアップの対象ではありません。
  ホスト・ボリューム全体の独自バックアップやスナップショットにはこのフォルダを含めないでください。
- 終了時の保存から5分でAPIの取得を拒否します。再取得しても期限は延長しません。
  ワーカーの独立した定期後片付け（既定30秒間隔）と起動時処理で期限切れファイルを消し、APIの取得時にも消します。
  全サービスを停止した間の物理削除は保証できないため、実演終了後にもフォルダを消します。
- 録音者本人だけが見られます。他の先生・管理者・保護者は閲覧できません。担当の引き継ぎでも閲覧権限は移りません。
- 本番へ切り替えた園では取得できません。ブラウザも表示期限・非表示化・離脱・認証失効で表示内容を消します。
- 一つの表示は最大40イベント、各8,000文字、合計256KiB未満です。暗号化済み結果は最大32件までです。
  上限時は一部表示を省略したことを通知し、音声処理自体は省略しません。
- 内容を含まない一時的な表示同意ファイルは最大24時間です。処理完了時に消します。

## 実演後

`.env` の `RECORDER_DEMO_TRACE_ENABLED=false` に戻してAPI・GPUワーカーを再作成します。
共有フォルダも次の操作で片付けます。下の例はVRTの既定パスを使用しています。

```bash
sudo docker compose -f compose.yaml -f compose.vrt.yaml exec -T api \
  python -c 'import shutil; shutil.rmtree("/app/data/recorder-demo-traces", ignore_errors=True)'
```

スクリーンショットや画面録画のコピーは自動消去できません。架空データを使う前提を守ってください。
